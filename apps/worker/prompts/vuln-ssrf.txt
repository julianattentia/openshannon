# EXECUTION PROTOCOL — FOLLOW EXACTLY IN ORDER

**CRITICAL CONSTRAINT: Each write_file/patch call must be under 200 words. Write one section at a time. Do NOT generate the full report at once.**

## PHASE 1 — Analysis (max 25 tool calls total)

Execute in order:

1. `read_file .shannon/deliverables/recon_deliverable.md`
2. `read_file .shannon/deliverables/pre_recon_deliverable.md`
3. Run these greps:
   - `grep -rn "fetch(\|axios\.\|http\.\|https\." src/app/api 2>/dev/null | grep -v node_modules | head -30`
   - `grep -rn "fetch(\|axios\.\|http\.\|https\." src/server/actions 2>/dev/null | head -20`
   - `grep -rn "url\|URL\|endpoint\|webhook\|callback" src/app/api 2>/dev/null | grep -i "request\|body\|params\|query" | head -20`
4. Read files with fetch() calls to determine if URL is user-controlled or hardcoded

Key question: is the URL passed to fetch() hardcoded/env-var, or does it come from user input (request body, query params, headers)?

**After 25 tool calls, STOP and go to Phase 2 immediately. No exceptions.**

### Step 2a — Create the file:

### Step 2b — Append: Executive Summary
Use patch to append a 3-4 sentence summary stating whether any fetch() target is user-controlled versus hardcoded/environment-configured. If <code_context> lists known outbound services, use it. Max 100 words.

### Step 2c — Append: Vulnerabilities Found

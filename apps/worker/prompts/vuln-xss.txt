# EXECUTION PROTOCOL — FOLLOW EXACTLY IN ORDER

**CRITICAL CONSTRAINT: Each write_file/patch call must be under 200 words. Write one section at a time. Do NOT generate the full report at once.**

## PHASE 1 — Analysis (max 25 tool calls total)

Execute in order:

1. `read_file .shannon/deliverables/recon_deliverable.md`
2. `read_file .shannon/deliverables/pre_recon_deliverable.md`
3. Run these greps:
   - `grep -rn "dangerouslySetInnerHTML\|innerHTML\|outerHTML\|document\.write" src/ 2>/dev/null | grep -v node_modules | head -20`
   - `grep -rn "eval(\|Function(\|setTimeout.*string\|setInterval.*string" src/ 2>/dev/null | grep -v node_modules | head -20`
   - `grep -rn "useSearchParams\|useParams\|searchParams\.get\|query\." src/app 2>/dev/null | grep -v node_modules | head -20`
   - `grep -rn "__html\|href.*{" src/ 2>/dev/null | grep -v node_modules | grep -v ".d.ts" | head -20`
4. Read source files flagged as containing potential XSS sinks (dangerouslySetInnerHTML usage)

**After 25 tool calls, STOP and go to Phase 2 immediately. No exceptions.**

## PHASE 2 — Write the deliverable (one section at a time)

### Step 2a — Create the file:
Use write_file to create `.shannon/deliverables/xss_analysis_deliverable.md` with ONLY:
```
# XSS Analysis Report — {{WEB_URL}}
```

### Step 2b — Append: Executive Summary
Use patch to append a 3-4 sentence summary. Note: pre-recon found one `dangerouslySetInnerHTML` in SplashHeroPage.tsx rendering CSS (not user input). Max 100 words.

### Step 2c — Append: Vulnerabilities Found
Use patch to append findings. For each sink found, document: source, render context, encoding applied, verdict. If none exploitable: write "No XSS vulnerabilities found. dangerouslySetInnerHTML in SplashHeroPage.tsx renders hardcoded CSS only, not user-controlled input." Max 200 words.

### Step 2d — Append: Vectors Analyzed and Confirmed Secure
Use patch to append list of sinks checked with their defense mechanism. Max 150 words.
